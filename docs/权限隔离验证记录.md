# 心屿 MindIsle v5 · 权限隔离验证记录

> 目标：证明「学生只看到自己数据 / 家长只看绑定孩子的趋势·情绪·AI建议 / 学校只看本校匿名聚合 / 社区只看区域汇总」四层边界成立。
> 双层防线：① Supabase 侧 = 001_init.sql 的 RLS 四角色策略（接入 Supabase Auth 后生效）；② 服务端侧 = 每个接口的 `needRole` 守卫（mock 与 Supabase REST 两种模式都生效，service_role 绕过 RLS，由路由守卫兜底）。
> 实测方式：mock 模式启动 `node index.js` → `node scripts/smoke.js`（31/31 通过）+ Invoke-RestMethod 手工链路，摘录见文末。

## 2. 每条边界 ↔ RLS 策略 ↔ 接口守卫对照

### 2.1 学生：只能看自己的数据

| 边界 | SQL 策略（001_init.sql） | 服务端守卫（server/routes/） |
|---|---|---|
| 只能看/改自己档案 | `users_self_select` / `users_self_update`：`id::text = current_uid_text()` | needAuth 解析 token → 只返回本人记录；所有查询带 `user_id = u.id` 过滤 |
| 只能读写自己的聊天 | `chat_records_self_select` / `chat_records_self_insert`：`user_id::text = current_uid_text()` | `needRole(u,['student'])` + `store.list('chat_records',{user_id:u.id})` |
| 只能读写自己的测评/情绪 | `assessments_self` / `emotion_records_self`（for all + with check） | 同上（仅本人过滤） |
| 只能读写自己的树洞 | `tree_hole_self`（for all + with check） | 同上；返回时剥离 user_id（匿名化） |
| 只能看自己的行为台账 | `behavior_self`（for all + with check） | 同上（仅本人过滤） |
| 学生看学校看板 → 403 | `school_cockpit` 视图口径 = 本人 school_id（学生只看到本校聚合，不含个体字段） | `needRole(u,['school'])` → 学生 403 |

### 2.2 家长：只看绑定孩子的心理趋势/情绪变化/AI 建议，禁聊天/树洞/私密

| 边界 | SQL 策略（001_init.sql） | 服务端守卫（server/routes/） |
|---|---|---|
| 经 family_bindings 读孩子情绪/测评 | `emotion_records_parent_view` / `assessments_parent_view`：`exists(family_bindings where parent_id = 当前用户 and student_id = 记录.user_id and status='active')` | `routes/family.js` GET /api/family/child：先查 `family_bindings{parent_id:u.id,status:'active'}` 再取孩子聚合 |
| **禁止读孩子聊天内容** | chat_records 无家长策略 → 默认拒绝 | 接口根本不提供家长聊天入口：`needRole(u,['student'])` → 403；family/child 响应不含 chat_records 字段 |
| **禁止读树洞** | tree_hole 无家长策略 → 默认拒绝；tree_hole_feed 视图仅授权 authenticated 且接口层学生专属 | `needRole(u,['student'])` → 403 |
| 禁止读孩子 AI 人格/画像/行为台账等私密 | ai_personality / user_behavior / family_bindings(他人) 无家长策略 | family/child 只返回：child 概要 + emotion_trend + emotion_distribution + assessments 摘要 + advice |
| 绑定只能绑自己 | `family_parent_bind`：`parent_id = 当前用户`（update） | bind 时校验 `row.parent_id` 空或等于本人，否则 409 |

### 2.3 学校：只看本校整体匿名统计（学生数/测评数/心理趋势/主要压力来源），禁明细

| 边界 | SQL 策略（001_init.sql） | 服务端守卫（server/routes/） |
|---|---|---|
| 本校聚合 | 视图 `school_cockpit` / `school_pressure_sources` / `school_emotion_distribution` / `school_trend_7d`：WHERE 内置 `school_id = 当前用户 school_id`，视图不含任何学生个体字段 | `routes/stats.js` GET /api/stats/school：`needRole(u,['school'])` + `store.list('users',{school_id:u.school_id,role:'student'})` 圈定范围后聚合 |
| **禁止看具体学生聊天/测评明细** | 学校角色对 chat_records/assessments/emotion_records/tree_hole 无任何策略 → 默认拒绝 | 所有明细接口 `needRole(u,['student'])`；stats 只输出 count/avg/分布 |
| 重点关注名单（脱敏） | 无直接表策略（服务端脱敏输出） | GET /api/stats/school/focus：仅昵称+测评类型/分数/分级/日期，**无用户 id、无聊天**；`?level=` 只按分级筛选 |
| 学校看家长接口 → 403 | family_bindings 无学校策略 | `needRole(u,['parent'])` → 403 |

### 2.4 社区：只看区域汇总（覆盖学校/服务人数/心理需求趋势）

| 边界 | SQL 策略（001_init.sql） | 服务端守卫（server/routes/） |
|---|---|---|
| 区域聚合 | 视图 `community_overview` / `community_needs` / `community_emotion_distribution` / `community_trend_14d`：WHERE 内置 `region = 当前用户 region` | `routes/stats.js` GET /api/stats/community：`needRole(u,['community'])` + `store.list('schools',{region:u.region})` 圈定后聚合 |
| 未设置 region 的社区账号 | 视图返回 0 行 | 接口返回空看板（region=未指定区域，计数为 0），不越界返回全量 |
| 禁止看学生个体数据 | 无任何明细表策略 | 明细接口全部角色受限；community 不在任何明细接口角色列表中 |

### 2.5 树洞匿名化（横切）

| 边界 | SQL | 服务端 |
|---|---|---|
| 公开流不含 user_id | `tree_hole_feed` 视图只投影 id/content/emotion/risk_level/created_time | tree-hole/feed 返回前 `anon()` 剥离 user_id（冒烟断言 `r.user_id === undefined`） |

### 3.2 手工复现关键边界（PowerShell Invoke-RestMethod）

```powershell
$b = 'http://localhost:3001'
# ① 家长不能聊天（应 403）
$pt = (Invoke-RestMethod -Method Post -Uri "$b/api/login" -ContentType 'application/json' -Body '{"username":"demo-parent1","password":"demo123456"}').token
try { Invoke-RestMethod -Method Post -Uri "$b/api/chat" -Headers @{Authorization="Bearer $pt"} -ContentType 'application/json' -Body '{"message":"你好"}' }
catch { $_.Exception.Response.StatusCode }   # 期望 403 Forbidden

# ② 家长看孩子：有趋势/建议，无聊天/树洞字段
$child = Invoke-RestMethod -Method Get -Uri "$b/api/family/child" -Headers @{Authorization="Bearer $pt"}
$child.bound -eq $true; $child.emotion_trend.Count; $null -eq $child.chat_records; $null -eq $child.tree_hole

# ③ 学校看板：匿名聚合，无个体字段
$st = (Invoke-RestMethod -Method Post -Uri "$b/api/login" -ContentType 'application/json' -Body '{"username":"demo-admin1","password":"demo123456"}').token
$stats = Invoke-RestMethod -Method Get -Uri "$b/api/stats/school" -Headers @{Authorization="Bearer $st"}
$stats.student_count; $stats.pressure_sources; $null -eq $stats.chat_records

# ④ 社区看区域汇总（王主任=上海市徐汇区，应只有阳光社区附小）
$ct = (Invoke-RestMethod -Method Post -Uri "$b/api/login" -ContentType 'application/json' -Body '{"username":"demo-com1","password":"demo123456"}').token
$com = Invoke-RestMethod -Method Get -Uri "$b/api/stats/community" -Headers @{Authorization="Bearer $ct"}
$com.region; $com.school_count    # 期望 "上海市徐汇区" / 1

# ⑤ 学生看学校看板（应 403）
$tt = (Invoke-RestMethod -Method Post -Uri "$b/api/login" -ContentType 'application/json' -Body '{"username":"demo-stu1","password":"demo123456"}').token
try { Invoke-RestMethod -Method Get -Uri "$b/api/stats/school" -Headers @{Authorization="Bearer $tt"} }
catch { $_.Exception.Response.StatusCode }   # 期望 403 Forbidden
```

### 3.3 Supabase 侧 RLS 实测步骤（需要用户项目凭据）

1. Supabase 控制台 SQL Editor 执行 `supabase/migrations/001_init.sql`；
2. 用演示账号数据确认表与视图：`select * from public.school_cockpit;`（以 SQL Editor 身份=postgres，看到全量）；
3. 创建测试 Auth 用户并把 `auth.users.id::text` 写入 `users.id` 一致的自建用户行（本项目服务端自管 users 表，RLS 在接入 Supabase Auth 后生效）；
4. 用该用户的 JWT 在 API Playground 直查：`/rest/v1/chat_records` 应只返回本人行；家长 JWT 直查 `chat_records` 应为空且 `assessments` 只含已绑定孩子行；学校 JWT 直查 `school_cockpit` 只有本校行。

### 4.3 缺口说明（Supabase 真实环境未实测）

RLS 策略与聚合视图为 SQL 静态交付，未在真实 Supabase 项目执行（需要用户提供 SUPABASE_URL + SUPABASE_SERVICE_KEY）。执行入口与验证步骤见 §3.3；服务端 Supabase REST 驱动（lib/supabase-driver.js）已按 PostgREST 协议实现并做连通性降级保护（连通失败自动回落 mock），但端到端实测依赖凭据。

## 5. 结论

- mock 模式（比赛演示路径）：四角色边界全部经 31 项冒烟断言实测通过；
- Supabase 模式：RLS 四角色策略 + 匿名聚合视图已在 001_init.sql 写清，与接口守卫一一对应；服务端 service_role 访问由路由守卫实施同等边界（双层防线）；
- 家长可见域严格限定为「趋势/情绪/测评摘要/AI建议」；学校/社区仅匿名聚合；树洞对外匿名化。
