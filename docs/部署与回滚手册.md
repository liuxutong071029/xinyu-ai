## 二、前端部署(GitHub Pages)

1. 打开 GitHub 仓库 `liuxutong071029/xinyu-ai`(旧文件一个都不删)。
2. 新建目录 `v3/`,把以下 7 个文件上传进去:
   - `index.html`(入口,必须全小写)
   - `styles.css`、`themes.css`(新)、`app.js`
   - `favicon.svg`
   - `frontend/assets/` 已包含全部 12 个小学端素材(宠物小猫/小狗、树洞大树、飞信、5 个心情图标、3 个零食图),随包一起上传即可;png),把整个 `assets/` 也复制进 `v3/`(这些是小学端/聊天页装饰图,新版引用路径不变;没有也不影响初中/高中主题功能,只会少几张装饰图)。
3. 等待 1-10 分钟构建,访问 `https://liuxutong071029.github.io/xinyu-ai/v3/`。
4. **验证缓存修复**:浏览器 Ctrl+F5 强刷一次;之后任何修改只需重新上传同名文件,因为资源带 `?v=3.0.0` 版本号 + 页面带 no-cache 头,不会再出现"必须手动刷新"的问题。页面底部有版本号 `v3.0.0 资源版本` 徽标,看到它就说明加载的是新版。
5. 旧版入口 `https://liuxutong071029.github.io/xinyu-ai/` 保持原样不动,即完成"新旧并存、随时回滚"。

## 五、Supabase 迁移(可选,比赛加分项)

1. 登录 supabase.com → 新建项目(免费额度即可)。
2. SQL Editor → 粘贴 `supabase/migrations/001_init.sql` 全文 → Run。
3. 验证:9 张表(users/schools/ai_personality/chat_records/assessments/emotion_records/family_bindings/tree_hole/user_behavior)+ 15 条 RLS 策略。
4. 服务器连库:
   ```
   SUPABASE_URL=https://xxxx.supabase.co SUPABASE_SERVICE_KEY=eyJ... node index.js
   ```
   再跑一次 smoke.js 即完成真实数据库验证。
5. 真实 AI 对话(可选):
   ```
   AI_API_KEY=sk-xxx AI_BASE_URL=https://api.deepseek.com/v1 AI_MODEL=deepseek-chat node index.js
   ```
   不配置时自动用内置规则回复(记忆引用/情绪识别/高风险提醒都可用),演示不受影响。

## 六、回滚手册

| 场景 | 操作 |
|---|---|
| 新版出问题 | GitHub 上删除 `v3/` 目录(或把 index.html 换回旧版),旧入口 `xinyu-ai/` 从未动过,即时回滚 |
| 后端出问题 | 停掉 server 进程即可,前端演示版完全独立、不受影响(localStorage 本地存储) |
| Supabase 数据要重置 | SQL Editor 执行 `drop table if exists users, schools, ai_personality, chat_records, assessments, emotion_records, family_bindings, tree_hole, user_behavior cascade;` 后重新执行迁移脚本 |
| 本地 mock 数据要重置 | 删除 `server/data/db.json`,重启自动重建 |
| 想回到旧版前端 | 旧版三件套完整保留在 `.cluster/xinyu-v4-20260814/DELIVERY/项目代码/` 与工作区附件目录 |
